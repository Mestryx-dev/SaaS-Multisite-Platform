# i18n — mestryx-platform

**Status:** SSOT for localization  
**Last updated:** 2026-07-23  
**Policy:** [09-delivery-approach.md](../09-delivery-approach.md) — `t('key')` from the first user-visible string.

## Surfaces

| Surface | Catalog location | Runtime |
|---------|------------------|---------|
| **admin** | `apps/admin/src/locales/{en,fr}.json` | `i18next` + `react-i18next` |
| **store** | `apps/web/src/i18n/locales/{en,fr}.json` | SSR `t(locale, key)` + `window.__MX_I18N__` for islands |
| **email** | `apps/api/src/modules/email/locales/{en,fr}.json` | `emailT(locale, key)` in templates |
| **packages/ui** | None | **Props only** — apps pass translated strings; EN defaults are Storybook/demo fallbacks |

## Key rules

1. **Flat dotted keys** (English path): `domain.segment.qualifier`  
   - Admin (legacy, keep): `nav.dashboard`, `auth.signIn`, `product.create`  
   - Store (new): `store.cart.loading`, `store.nav.cart`  
   - Email (new): `email.order.confirmation`
2. **Values** are locale prose — no Franglais (`Preparing your boutique` is forbidden).
3. **Interpolation:** i18next / store `{{count}}`, `{{name}}`.
4. **Aria:** same key when identical, or `*.aria` sibling when different.
5. **Do not** mass-rename existing admin keys to `admin.*`.

## Locale resolution

| App | Source |
|-----|--------|
| Admin | `localStorage` `admin-lng` → fallback `en` |
| Store | `site.defaultLocale` (`en` \| `fr`) → fallback `en` |
| Email | Site / order locale → fallback `en` |

## Parity CI

```bash
pnpm check:i18n
```

EN and FR catalogs for each surface must have the **same key set**.

## Anti-patterns

- Hardcoded user-visible FR/EN in JSX / `store-chrome.js` / email HTML
- Putting `react-i18next` inside `packages/ui`
- Translating CMS page bodies here (out of scope — content localization is separate)
